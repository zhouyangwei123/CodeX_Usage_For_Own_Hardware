# 0.5.1 USB 升级安全修复与本机验收

基线为 `review/usb-ota-20261022` / `ea643ff`。用户要求修复三项审查问题、更新本机、离线和实机验证后推送分支，并规划 OLED 与 USB 调试。本轮上位机为0.5.1，未修改App0.9 / Boot1.0源码和布局。

## 修复行为

1. 正常升级前从当前CDC串口的Windows PNP身份取得USB序列号，进入DFU前再次核对。更新器必须收到预先确认的身份；若DFU只出现另一序列号，立即拒绝，连该设备的内存都不读取。无串口的恢复流程先“识别设备”，在确认框显示并绑定序列号，后续操作不改变目标。
2. 升级状态由BridgeService统一持有，同一时刻只允许一个升级。托盘退出和ApplicationContext.ExitThread在清理窗口、设备服务前检查状态；升级结束后才释放。设置窗口普通关闭限制保留。完成与错误路径均在恢复串口后释放状态。
3. 首次安装在第一次写入前检查WRP1B是否覆盖安装范围，同时检查Bank1 PCROP。按当前DBANK计算页大小和最后受影响页；遇到冲突停止，不自动解除保护。安装区域外的WRP1B保留。
4. 移除浮窗悬停ToolTip，保留折叠、拖动、额度与底栏；主动保存失败时仍提示错误。

## 本机实测与部署

识别到ST-Link及同一块STM32G474RB / 128 KiB板卡，串口为COM6。只读核对得到Boot1.0/App0.9，CRC与交付镜像匹配，WRP1A保护前8KiB，WRP1B未启用。测试后的前64KiB Flash和选项字节与测试前完全一致。

新版生产SerialLink通过10次Reconnect与10次Pause/Start，均取得新握手和INFO。随后连续通信300.008秒，1192/1192回显，无未回答或意外回显、运行时间倒退及意外断连，最大往返8ms；释放后独占打开检查成功。这不是8小时验收，也不覆盖系统睡眠或物理拔插。

原上位机0.4.2已正常退出，原EXE与配置留有本地备份；安装目录EXE已更新为0.5.1并启动。个人配置、认证与芯片备份不纳入仓库。
