# 命令行本机全部会话合计

本轮按用户要求将独立测试窗口默认扩展到本机全部`sessions`与`archived_sessions`日志；保留单会话参数用于对照。上位机和设备固件本轮不接入这个实验。

## 合计与归零

每个会话选取最新轮次，沿用最近5个有效响应的时间加权速率及0.35系数EMA；当前合计为这些会话速率之和。合计值不再叠加一次EMA，因此会话结束后会立即从合计中移除，全部结束后为0。未取得测速数据的活跃会话单列为待测速，已有数值只表示已测速部分。

本机近60秒输入、输出用量按真实响应去重后求和；轮次结束不会抹掉历史用量，记录自然移出60秒窗口后才回落。超过60秒的旧测量不再代表当前速率，历史未闭合记录不会永久占速；这也意味着长时间没有新日志时显示的是“等待近期样本”，不是捏造持续生成速度。

会话身份来自文件元数据与事件thread_id，轮次以(thread_id, turn_id)隔离。新分页、会话与归档每3秒发现一次；文件移动或分页重放继续使用同一去重状态，同一响应跨来源复制也不会重复计数。缺少轮次起点的5份历史响应仍纳入本机用量，但不据此生成速度。本轮实读35份日志，20个有相关记录的会话，均具有现代响应计数。

## 验证

50项构造检查通过，覆盖两会话100+200=300、一方结束降为200、全部结束立刻0；还检查停止与迟到用量、相同轮次ID跨会话、复制/分页/归档去重、新会话发现、旧未闭合记录、待测速来源及诊断文件被读占用。诊断输出只是可选测试记录，暂时无法写入不能关闭可见面板。

独立地逐条读取35份日志的原始响应记录后，按响应ID去重，与面板核对：1268份响应的数量、输入合计、输出合计均一致。这个独立快照与后续连续检查发生于不同时间，活动日志会继续增长。

连续真实日志检查300.297秒、593轮通过：最多同时观察到2个活跃且已有测速的会话，合计始终等于来源速率之和，响应ID未重复累计，消耗合计没有回退，期间9轮检测到新的测速结果。验证进程的单核平均CPU占用约1.31%。这属于本轮5分钟初步检查，不代表长时间稳定性已完成验收。

在真实收集状态的内存副本中，将所有会话标记结束后当前合计为0，近60秒消耗及累计保持。详见[结构化证据](evidence/token-rate-local-20261028.json)。内存回放不修改实际日志，也不停止用户任务；不把它写成用户全部任务真的被停止。可见窗口已验证为本机模式并持续刷新，后续先保留命令行观察，按用户要求暂不接入上位机。

## 使用

```powershell
python -X utf8 tests/token_rate/live_console.py
python -m unittest discover -s tests/token_rate -p 'test_*.py'
python tests/token_rate/verify_all_sessions.py --seconds 300 --output artifacts/token-rate/all-session-soak.json
```

窗口保留当前合计、活跃/已测速/待测速数、本机近60秒消耗及已读累计。仍然每0.5秒刷新，速度随响应完成更新，不声称逐Token精确实时。按Q或Ctrl+C退出。历史单会话测试及算法比较见[前期记录](TOKEN_RATE-20261028.md)。
