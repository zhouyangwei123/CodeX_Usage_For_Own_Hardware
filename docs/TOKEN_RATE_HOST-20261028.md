# Host0.6.3 本机全部会话输出速率

本轮将用户已确认的命令行方案接入原生上位机。本机模式缺省统计本机`sessions`与`archived_sessions`中可读取的全部会话，无需选择当前聊天，也无需另开Python。保留用户现有来源选择；新配置仍默认为本机、像素皮肤。

## 数值与显示

每个会话只取最新轮次，以(thread_id, turn_id)隔离；按response_id全局去重，分页、归档和分叉副本不重复累计。只合并Reasoning/AgentMessage计时区间，排除工具执行时长。最近5个合格响应按时间加权，再用0.35系数EMA平滑，最后将各会话结果相加；不对合计再加EMA。单次计时至少250ms、累计有效计时至少1秒；不合法计时在内部跳过，后续有效记录可继续测速。

轮次完成或停止时立即从合计中移除，全部结束后为0；迟到用量不重新激活已结束轮次。未有完整计时的会话列为待测；全部待测时显示`--/s`。超过60秒的旧测量不代表当前速率，历史未闭合记录不会永久占速。这里是最近响应的近似输出速率，更新发生在响应完成后，尚无逐Token流作为本机真值。

普通皮肤与像素皮肤主值均显示`123/s`，同时保留分钟输入、输出。曲线仍表示最近60秒输入加输出的消耗，保持35像素高度与一行底栏。输入包含缓存、输出包含推理，不重复相加。账号来源继续展示服务端日汇总。

同一账号的额度刷新短暂失败时，上位机保留最近成功的百分比、倒计时和进度条；读取层仍保留失败状态，未将旧值标为新获取。退出登录、账号变化或从未成功读取时仍显示空值。实体屏幕的过期标志与显示保持原协议行为。问题定位与验证见[额度显示修复](QUOTA_VISIBILITY-20261028.md)。

沿用同一个带预算的读取服务：已知日志每0.5秒检查，新会话/分页/归档每3秒发现，HUD最多每秒更新一次。单次读取32MiB与原有取消、文件偏移、隐私约束继续使用。计时事件只瞬时解码，保留标识与数字；不持久保存正文，不读取认证资料，不将私人日志入库。

## 离线及本机验证

- Python命令行50项检查通过；原生上位机126项检查通过，包括7组、53个跨语言对照点、并行100+200、逐一结束、全部归零、停止与迟到用量、重叠计时、短计时累积、分页去重、最新轮次选择，以及真实.NET服务对新增归档的发现。
- 原有活动30组、用量26组、HUD77项与渲染/GDI检查通过；账号/OLED/皮肤203项、26组完整1024字节帧比较、216种Demo栅格状态通过。实际发布EXE的自检与模拟链路检查通过。
- 冻结35份本机日志的6016条计时元数据、去除消息正文后，Python与C#取得相同20个来源、相同活动/已测速数量和合计速率。原始日志不修改，元数据副本留在忽略目录。
- 本机已安装并启动0.6.3.0；安装检查确认EXE与已测发布文件逐字节相同，配置原样保留，来源为local、皮肤为pixel。未烧录固件。
- 正式EXE程序集的原生读取服务连续检查300.077秒通过，取得580次有效快照、16次速率变化；测试进程单核平均CPU约3.85%、峰值私有内存37.07MiB。本段只观察到一个活跃且已测速来源，没有实际全空闲时段；多来源并行和全部结束由上述构造回放与.NET定时服务检查覆盖，不冒充本段真实并发观察。

连续原生服务检查及USB实机验收结果见[结构化证据](evidence/token-rate-host-20261028.json)。5分钟初步检查不能替代长时间运行、睡眠唤醒或物理拔插验收。

## 设备及交付范围

本轮接入范围为上位机：串口分钟用量帧及STATUS保持，PC_METRICS v3仍为28字节，实体OLED继续显示原有tok/min。实体屏幕同步TPS需要另行修改协议与固件；本轮未将TPS塞进分钟字段。当前固件仍是此前选择的App0.12温和三档，保留1Hz用量页。

本轮尚未完成设备USB通信验收，待设备接回后另行执行。本机日志、模拟链路及历史App0.12结果不代替本轮USB验证。本次仅发布上位机0.6.3，安装包与更新方法见[正式发布说明](RELEASE-0.6.3.md)。
