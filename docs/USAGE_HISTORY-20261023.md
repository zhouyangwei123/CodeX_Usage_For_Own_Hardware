# Host0.6.2：启动历史曲线修复

用户反馈像素浮窗纵轴为0、0.5、1，曲线全空；本机日志实际上存在最近一小时的用量。此刻度来自全零曲线的最小自动量程，不是合成测试数据。

根因是扫描器把相同会话ID的多个文件一律视为完整日志副本，只保留事件数较多的一份。当前Codex桌面日志使用`session_meta.history_mode=paginated`，恢复会话后会产生新的分页文件；旧分页事件较多，新分页的近期用量被排除。因此“目录存在、扫描完成、协议发送成功”不能证明曲线已覆盖真实用量。

0.6.2对明确标记为paginated且父会话一致的文件按数值事件时间合并，先去除重叠页/归档副本，再沿用累计差分与分叉继承处理。未标记为分页的日志仍使用原有副本一致性检查。采集服务、曲线时间窗口和设备协议保持原行为，无新增缓存或第二个统计来源。

启动读取完成后按事件原始时间补回最近一小时，不把旧数据算入当前分钟；底栏为最近60秒已上报用量。纵轴是Token/分钟，峰值按1/2/5整档自动缩放。最近一小时都无记录时，全零曲线及0、0.5、1刻度仍属正常情况。日志缺失、非法计数和旧超长行的覆盖警告继续保留，修复不承诺补回不可读记录，也不把当前值当成逐秒生成速度。

## 本轮验证

- 修复前同一真实日志源扫描完成后近期事件为空，最后采纳事件已超过一小时；修复后首次扫描即恢复过去曲线与当前非零用量，记录均使用原始时间。只保存状态和布尔结果，不提交个人Token值。
- 新增两组分页回归，覆盖启动补画、归档去重、重叠去重、历史累计基线、空闲时保留过去曲线、冷启动重建、增量追加。修复前均失败，修复后本机活动30组、原用量统计26组全部通过。
- Token HUD77项、账号/OLED/皮肤203项、26组完整C/C#帧比较、216种Demo栅格组合通过；内置自检86项、模拟4项通过。
- 最终Host0.6.2通过生产LocalUsageService、BridgeService和SerialLink连接同一实机App0.10；确认历史曲线非零并实际发送到设备、来源切换、输入输出合计、PC帧28字节、OLED在线和无错误ACK。此轮未重新刷固件，未重做USB写入或五分钟稳定性测试。
- 本机上位机原路径已替换并重启；安装文件与本轮测试构建一致，用户配置逐字节不变，默认本机/像素/页4继续生效。旧EXE保留本地备份。
