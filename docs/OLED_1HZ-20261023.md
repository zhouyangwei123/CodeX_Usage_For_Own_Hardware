# App0.11：用量页1Hz写屏试验

用户反馈实体OLED有噪音，希望无动画的额度/波形页按数据更新降到1Hz；本轮附图由用户明确撤回，不作为故障证据。

原代码在Codex运行时每100ms重绘、其他状态每500ms重绘，即基准10Hz/2Hz；`oled_dirty`还能绕过周期立即刷新。只把周期常量改成1000ms无法限制收到STATUS、PC或用量消息后的额外写屏。

App0.11对本机波形页4和账号额度页0采用1000ms最小间隔，期间收到的消息合并，下一次绘制使用最新数据。绘制后比较完整1024字节画面，相同内容不再写入OLED；比较复用已有DMA发送缓冲，不增加一份屏幕缓存。DMA失败、异步I2C错误或重新初始化不会把失败的画面当作已写入状态。PC监控页和原有噪音诊断时序保持，主循环5ms、串口/按键处理和RGB周期未调整。

这里1Hz指内容重绘/写入频率，不是OLED内部扫描频率。屏幕内部时钟、预充电和亮度参数本轮未变。软件检查能证明调度与传输行为，听感是否改善需要用户比较实机，不能仅凭降低写屏次数宣布消除了噪音。

## 已完成检查

- 原调度在每5ms数据事件测试下，12种页面/状态组合均突破1Hz；修复后每10秒恰好10次调度。覆盖32位计时回绕、PC页40ms周期、事件即时处理与诊断入口。
- 完整生产OLED驱动仅替换HAL总线边界进行测试：SSD1306/SH1106均验证相同画面100次无I2C写入、变化帧恰好1024字节、DMA忙/待发内容回退、阻塞降级、写入错误和重新初始化。
- 原203项账号/OLED/皮肤检查、26组C/C#完整帧比较、216种Demo栅格状态通过；镜像9项、升级请求3项、更新器55项及Windows PowerShell5.1中文路径检查通过。
- ARM Release构建0错误0警告；封装应用47,592/57,344字节，data+bss为14,728字节。Boot1.0源码及封装未改。
- 实机通过生产USB更新器从App0.10升级到0.11并独立回读一致；整个8KiB启动区与44字节选项保持，错误身份在内存操作前被拒绝，升级期间退出保护有效。重新连接取得0.11 INFO。
- Host0.6.2的生产真实数据链路确认本机/账号来源可用、历史曲线非零、输入输出合计与28字节PC帧正确、OLED在线、错误ACK为0。已恢复原日常上位机与本机页。未采集实际I2C波形或声压，不把离线调度次数当作仪器实测刷新率；本轮未重复五分钟或长时间稳定性测试。

2026-10-26用户反馈：噪音没有显著好转，认为此前随机频率方案效果更明显。这是主观对比反馈，不是声压测量；后续选择温和三档内部时钟扰动，见[App0.12试验](OLED_GENTLE-20261026.md)。[本轮结构化检查结果](evidence/oled-1hz-20261023.json)。

## 使用

离线复验：`tests/oled_refresh/run.ps1 -Python <python路径>`，需gcc；原绘图复验仍用`tests/oled_usage/run.ps1`。测试生成物、完整芯片备份和个人配置仅在忽略的`artifacts/oled-refresh-20261023/`保存。
