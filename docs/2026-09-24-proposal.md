## 4. P0：额度可靠性与后台效率

推荐保留现有 WinForms 与单 EXE 分发，先修数据链路，再调整外观。

### 数据模型

额度快照按账户、提供方、limitId 隔离，保留窗口时长、重置时间、采样时间、最近成功时间和错误类别。状态明确为：新鲜、陈旧、尚无数据、登录失效、不支持。不能把缺失字段当成 0%，也不能把陈旧快照标成实时数据。

- 合法的单窗口响应：该窗口正常显示；明确不存在的第二窗口不伪造、不从旧窗口继承。
- 空对象、缺少必要字段、格式错误：判为无效响应；同一账户下保留最近成功值并标明时间。
- 稀疏推送：字段未出现表示未更新；显式 null 的含义按协议区分。只接受目标 limitId。
- 账户更换、退出登录或数据来源更换：切断旧快照归属，避免把上一账户的用量显示为当前账户。
- 长期陈旧：界面明确过期；不无限保留成“可用剩余”。

### 调度与恢复

使用一个受取消令牌管理的长期 Codex 连接、一个异步刷新循环。最多一个活动请求，周期刷新和手动刷新合并，不无限排队。持续读取 stdout/stderr，日志仅保留限量、脱敏内容。

对短暂网络失败指数退避；连续超时后只重启本工具拥有的 Codex 子进程。停止、重连、退出时取消等待并清理所有定时器和请求。账户权限问题给出明确提示，不循环高速重试。配置保存采用先验证、临时文件、原子替换、备份与可回滚迁移。

建议起始频率：额度 30～60 秒；账户日统计 5 分钟；本机会话日志增量读取约 1 秒。PC 监控先保留当前约 1 秒周期，根据实测再调整。关闭某个集成时停止其采样；设置页隐藏时不持续重绘。桌面日志读取使用增量游标和轮转检测，评估连接复用，避免每次扫描全部历史。

串口发送保持当前协议与必要心跳频率，不为减少发送量破坏固件超时判断。一次推送使用同一份不可变快照，防止并发更新导致字段前后不一致。

### 一期文件范围

- 修改：`host/src/Quota/CodexStatusProvider.cs`、`ProcessJsonLineTransport.cs`、`JsonLineRpcClient.cs`、`Model/QuotaSnapshot.cs`。
- 修改：`host/src/Core/BridgeService.cs`，让额度健康、桌面活动、PC 监控、设备通讯分别可观察。
- 按必要性新增：额度解析器、诊断快照和测试文件；避免在第一步大规模重构不相关模块。

## 6. P2：Token 统计

三种数据分别展示，不互相相加：

| 数据 | 推荐来源 | 更新与边界 |
| --- | --- | --- |
| 账户额度百分比与重置 | `account/rateLimits/read` | 代表账户限制，不等于 Token 总量 |
| 账户今日/历史 Token | `account/usage/read` | 已验证接口可用；聚合统计延迟、日期时区和跨设备范围需核对 |
| 本机会话 Token | 本机 rollout 中的 token_count 增量 | 可展示输入、缓存输入、输出、会话累计、最近活动；仅覆盖实际存在的记录 |

`thread/tokenUsage/updated` 是官方支持的会话用量事件，但另起一个 app-server 不等于自动订阅了桌面端全部活动。只有确认事件来源覆盖目标任务时才使用；否则只读追踪本机日志。

本地统计需处理重复事件、累计值差分、文件截断/轮转、归档、恢复/分叉继承前缀、多任务与子代理去重。上下文占用和累计 Token 单独标注。缓存输入是输入的子集，不能重复计入总量。

可以显示“近实时”，但精确度取决于上游事件更新；不能承诺逐 Token 实时或精确 tokens/s。可以提供最近一分钟增量/平均速率，并明确统计时间窗。按 API 价格折算的金额只能标注估算，不当作订阅扣费或余额。未知模型价格显示未知。

推荐第一版自行实现轻量 C# 增量读取，使用 ccusage 作对账参考；先用有限样本对照，再扩大覆盖。不要每秒启动外部 Node 工具全量扫描会话目录。DeepSeek Harness 在确定实际日志/事件格式后另建适配器，不重新写入 Codex 的配置。
