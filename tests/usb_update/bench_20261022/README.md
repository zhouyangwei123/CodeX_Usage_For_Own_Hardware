# 已执行的实机测试程序源文件

这些文件与2026-10-22实际测试时的源文件逐字节相同。结果在 `docs/evidence/usb-update-20261022/`，适用范围与失败记录见 `docs/USB_HANDOFF-20261022.md`。它们作为开发复现材料保存，不会被构建或安装脚本自动运行。

| 文件 | 当时实际用途 / 使用限制 |
|---|---|
| SerialProbe.cs | 明确指定COM号、完整PNP身份、输出JSON和时长；独占打开，仅PING/CFG_REQ。原机短测通过。关闭阶段在底层阻塞时可能超出采样时长，需外部进程期限，不能抢占其他程序 |
| SerialLinkBench.cs | 引用交付EXE的SerialLink，20次重连与300秒通信；固定COM8和本板序列号，先用原生独占句柄检查占用 |
| EnterDfu.cs | 生产SerialLink验证固件版本后发软件DFU请求；会使设备重启，固定本板身份 |
| HardwareUpdateRunner.cs | 调用交付EXE的首次安装/USB更新代码，额外核对本板与探针身份；会写入设备，不能把本夹具的防护当作产品已有防护 |
| native_read.py | 通过指定探针直接读固定的两段Flash或选项地址；仅允许本轮容量范围。探针读取也可能影响执行状态，不能当作无影响监控 |
| partial_app_test.py | 受控写入不完整应用，再验证恢复；会故意破坏应用的完整性，固定本机路径，依赖原机备份，不能作为日常更新脚本 |

异地首先使用整理包的正常升级界面及KEY1入口。只有继续复现实验时才适配上述源文件的路径与当前COM号；不要删除设备身份检查来绕过不匹配，也不要在其他程序占用串口时继续。涉及写入的程序需重新确认实际目标、所有权、有效备份和恢复条件。

`SerialProbe.cs`可用Windows .NET Framework C#编译器编译，引用 `System.Management.dll`、`System.Web.Extensions.dll` 和整理包的 `CodexToolsHost.exe`；把生成EXE与该被测EXE放在同一个独立目录。运行参数依次为：串口名、完整PNP身份、输出JSON绝对路径、采样秒数。本板的USB应用身份为 `USB\VID_0483&PID_5740\20553872524E`；COM号应在新电脑重新核对。

这里保留当时程序，未因迁移需求重新设计或补齐全部函数注释；不表示已完成这些测试辅助程序的代码验收。
